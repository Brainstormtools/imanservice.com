# Private additional-scope budget drafts

Administrator → Project configurator → Private additional-scope budget drafts.

Choose an exact client-Accepted additional BOQ offer. Currency is fixed from that source. Enter the draft title, optional internal notes and actual cost lines manually: existing quotation block (Material, Labour, Inventory or TADA), description, unit, positive quantity and nonnegative planned unit cost. No quantity, rate, cost block, salary, tax or reviewer is prefilled. Explicit zero cost is accepted when the administrator intentionally records it; unknown values should not be represented as an inferred zero.

Save with a reason. The server rounds each quantity × unit-cost amount, sums the draft and existing block totals, freezes the exact accepted source and original conversion budget, and records the actual actor/time. A source has one versioned draft. Revisions require the displayed current version and a new reason; every before/after record is retained. Exact creation/revision retries return the same ID, including a delayed creation retry after later draft revisions; changed/stale retries cannot revert current costs or duplicate a proposal. Failed saves keep entered fields. Refresh reloads access and discards the current editor.

The private register exposes current cost lines/totals, original baseline/source and reasoned revision history. Its draft CSV contains only the administrator-visible current cost proposals and actual creators/reasons. Clients, assigned managers, workers and disabled/anonymous users have no access to these new cost tables or controls.

Review the exact current draft version with an explicit manual reason. An active administrator can return a version with a correction reason; a returned review cannot release. Release requires the exact latest Reviewed action and matching frozen cost snapshot. The actual authenticated reviewer/releaser and time are recorded, without an invented named reviewer assignment. The implementation does not impose an undocumented distinct-person approval policy. Only Released versions lose review/return controls; revise the draft to propose a new version, which requires fresh review. Earlier releases remain immutable and visible alongside the current proposal. Exact delayed action retries retain their original identity without reverting later proposals. Changed action payloads require a fresh identity.

The private review-history CSV includes action order, exact version/review reference, frozen complete budget, actual actor/time and manual reason. Failed/revoked reads clear the parent archive and action controls; refresh rechecks access. Completed projects and released handovers prohibit new budget actions.

The latest **Released cost snapshot per accepted offer contributes to effective financial planned costs**, alongside the immutable original conversion budget. Later drafts/reviews/returns retain the prior effective release until a newer release replaces it. Distinct accepted offers add once each. Explicit zero costs remain recorded; missing original budget totals stay unknown. Project Financials and its CSV/PDF separate original, released-additional and effective costs and recompute remaining/utilisation/planned-profit values. Existing authorized Accounts/assigned managers receive aggregates without gaining private draft/history access. This increment does not allocate money, change the original sale/budget, issue invoices, change salaries or alter client-approved selling scope. Contract/revenue values remain the original sale basis; profit labels and export notes state that additional selling values/revised contracts are still pending, so this is provisional financial planning. Tax/charge treatment, product allocation and subsequent material-request quantity adjustments remain pending DEV-029 work. The client owns actual signed-in/browser/download/device acceptance.

Material request and purchase-order approval limits now use the original conversion Material budget plus the latest released Material contribution per accepted offer. Labour/Inventory/TADA releases do not increase that limit. Existing configured thresholds, cumulative commitments, actual-rate PO deltas, requester/creator separation, overrun reasons and distinct manager/administrator approvals remain unchanged. No funds, purchase order or catalogue mapping is created by releasing costs. Non-project/missing-original-material handling preserves the existing procurement zero-baseline rule; unknown financial total costs remain unknown. Initial additional requests use exact approved catalogue mappings as described below; subsequent quantity adjustments remain pending.

For the latest released cost version, choose **Prepare material mapping draft**. Manually select a released Material cost line and an actual active consumable Quantity/Serial catalogue item. Enter actual stock quantity in the displayed catalogue unit and a reason. Cost-plan quantity/unit is context; it is never converted/copied into stock quantities. Quantity items use at most three decimal places, Serial items require whole units; existing combined stock-request limit is 100,000 per catalogue item. Blank inputs are not filled automatically. Returnable tools and product/workstream allocation remain separate.

A mapping starts as a private unreviewed draft. Save/revise freezes actual catalogue name/unit/tracking/version and exact released source, retains before/after/actor/reason history and supports scoped CSV. A newer cost release leaves the earlier mapping archived; prepare a separate mapping for the newer release. No material request, reservation, purchase, funding or assignment is generated. Review or return the exact current mapping version with an explicit manual reason. Approval rechecks unchanged active catalogue identities/units/tracking/versions and freezes the complete reviewed mapping. Catalogue changes require an explicit mapping revision before approval. Return retains the old approved archive and changes current state; a later mapping revision needs fresh review. Actual authenticated administrators and timestamps are recorded without invented reviewer assignments. Review history/CSV and older-source archives remain private. Prepare an initial material request separately after approval; product allocation and later quantity adjustments/replacements remain pending. Approval itself creates no request or reservation.

For a currently approved mapping, **Prepare reviewed material request** fixes the approved stock quantities and requires manual purpose, actual delivery site, need date and generation reason. Confirm explicitly that these additional quantities have not already been requested manually/through another source; unlinked manual requests cannot be detected automatically. The resulting MR is Requested and must continue through existing stock checks, reservations, requisition/PO approvals and fulfilment. It creates no task/worker assignment, reservation or purchase automatically.

Only one initial MR is generated per accepted additional offer, including across later cost releases/mapping revisions. Exact retries return the same MR; changed retries/new identities cannot duplicate it. Return/reapproval or cancellation does not silently create a replacement. Manage an existing request through the existing supply workflow; subsequent quantities/replacements need a separately documented workflow. Private receipt/CSV contains frozen original creation data and actual actor/reason/confirmation, not current supply status.

**Additional material request history** appears within the accepted offer's private budget draft even when its latest cost release has no mapping yet. Open the original request receipt to inspect its frozen request/lines, approval/mapping source, manual header and unrequested-quantity confirmation, actual actor/time and reason. Export its individual receipt CSV for the complete frozen evidence. Newer releases/mappings do not remove this history or permit another initial request. The displayed Requested status is the original creation status; use the supply workspace for current status. Refresh after a read/download error to recheck access and retry.
