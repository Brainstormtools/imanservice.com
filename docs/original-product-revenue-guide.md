# Original product revenue reference

Active Admin or Accounts (`finance.manage`) opens **Finance → Original revenue reference**, then chooses the actual PKR project. The project starts blank. This is a read-only reference to the project's original accepted quotation before quoted tax; it is not revenue recognition, BOQ adoption or a product-profit calculation.

The view shows actual original sale/publication identity, quotation number/revision/source version, server read time/Pakistan business date, original quoted subtotal, reconciled item reference, mapped amount and unattributed amount. Missing original acceptance or unreconciled item evidence remains Not recorded rather than zero. No original item CSV is available when actual item evidence cannot be reconciled.

Published client items contain frozen product wording but no stable product IDs. Mapping is established only where the original frozen quote budget equals the converted sale's saved budget, its calculation contains the exact accepted client items and internal lines, and the existing migration-016 publication algorithm reproduces all accepted items exactly. Only frozen data is used, including the original stored prices/margins through that existing algorithm; no new pricing or rounding policy is configured. Stable original line/product IDs come from that frozen evidence. A current workstream must belong to that original sale, project and product/deal. Current mutable quote lines and renamed product labels are not mapping evidence.

Missing, inconsistent or malformed frozen mapping evidence leaves the actual accepted item amounts unattributed. A matching product label is never enough. Missing original-sale workstreams remain unattributed even when an original product ID is known. Commercial adjustments, including negative adjustments, remain separate and unattributed; they are not spread over products. Thus mapped material references can exceed an adjusted overall subtotal, with the signed adjustment reconciling the difference. Repeated labels retain separate original positions and identities.

**Export original product revenue reference CSV** retains the actual loaded project's original source/read identities, original item position/wording/amount, established original line/product/workstream IDs, mapping state and limitations. It excludes private unit costs, vendor data, margins and full budget snapshots. Unresolved mappings with valid original items can be exported with explicit unattributed status. Manual wording is escaped for CSV.

Refresh clears the project selection and prior evidence; choose the actual project again. Failed source reads/exports and account/authority changes clear old private rows/exports. Late prior-project/account responses cannot restore them. Clients, workers and PM-only accounts receive no new access. Existing actual Accounts/Admin authority is checked by the server on each read.

Accepted additional BOQ/contract references remain separate under migration 076. This reference changes no actual quotations, product mapping records, workstream/assignment, source ledger, invoice/payment, tax/WHT treatment, cost, cash, operative project financial total or profit. DEV-042 broader product financials and client signed-in/live/browser/export/device acceptance remain pending.
