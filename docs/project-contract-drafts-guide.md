# Private project contract revision drafts

Administrator → Project configurator → Private project contract revision drafts.

Choose an exact client-Accepted additional BOQ offer with recorded consent. Enter the proposal title, revision summary, proposed contract terms, proposed payment wording and revision reason manually. New fields are blank. Do not substitute assumed legal terms, amounts or payment policies for actual business input. Source currency is fixed; the draft does not calculate a new contract value.

Save the private unreviewed proposal. One versioned draft is allowed per accepted offer. The original accepted source and complete original Sale record are frozen as administrator-only evidence, including its private planning basis. An expected-version amendment retains those original snapshots, records actual actor/time/reason and archives both old and new wording. Failed saves retain fields and retry identity. Exact delayed retries return the same draft without restoring earlier wording; changed or stale requests must refresh before editing. Completed projects and released handovers block further saves.

Inspect current proposed wording and frozen source under the draft. Export the private current-draft CSV or its reasoned revision-history CSV. These contain private sale/source evidence and are available only to active administrators; clients, managers, workers and anonymous/disabled users have no access. A refresh rechecks authorization and closes unsaved editors. After a read/download failure, refresh to recheck access and retry.

A saved draft is internal and unreviewed. Exact-version internal review/return is available below. Fixed client publication/withdrawal and explicit client accept/decline are available below; operative contract/revenue integration remains subsequent development. Saving does not amend the original sale, accepted BOQ, invoices, budget, funding, material requests, actual assignments or existing AMC/SLA contract documents/settings. No external email/SMS/WhatsApp is sent. The client owns signed-in workflow/export/device acceptance.

Review the exact current wording version with a manual review reason, or Return it with actual correction wording. A Reviewed action freezes the complete private draft, accepted source and original Sale basis. Return keeps earlier reviews immutable and changes current state; a new explicit review can follow. An amendment to the draft needs a new review for its new version. Actual administrators/timestamps are recorded; no named or distinct-person reviewer assignment is imposed. Completed projects/released handovers block review actions.

The current version state and private review archives appear within the draft. Export the private review CSV to retain exact versions, ordered actions, actual actor/time/reason, complete frozen proposals and canonical requests. Earlier reviewed snapshots stay frozen after wording amendments. Exact retries return the same action without restoring previous state. Failed action input/retry identity is retained; refresh rechecks access after read/download errors. An internal Reviewed action is not client sign-off and changes no operative contract value, legal/commercial terms, budget, invoices or AMC/SLA settings.

For the current Reviewed wording version, **Publish reviewed contract version** requires an actual manual reason. Review all manually entered wording for client suitability before publishing. The fixed client copy includes only proposed title/summary/terms/payment wording and the already-public accepted commercial source. It excludes the complete original Sale/budget/private costs and review/publisher evidence. Private publication provenance retains those exact review/source references separately. Publication itself is not client acceptance or an operative amendment.

One wording version is published once. Withdraw an obsolete open publication with a manual reason before publishing newly amended/reviewed wording. Withdrawal preserves the original copy and timestamps; it changes no scope, money or execution. It remains available for an obsolete open copy after project completion. Exact retries return the same action without reopening withdrawn copies. Use the private publication-history CSV for actual actor/reason and complete private review evidence.

Client → Agreements → Published project contract proposals shows fixed wording, accepted commercial source and Published/Withdrawn archives for the client's own company while the current project customer matches. The public CSV contains only allowlisted public fields. It queries no private draft/review/provenance tables. Customer/profile/read changes clear or re-scope access; refresh after a read/download error to retry. Explicit client accept/decline is available as described below; operative application remains pending development, and the client owns live workflow/export/device acceptance.

Client → Agreements → Published project contract proposals → Accept or Decline the exact open fixed copy. Enter an actual manual decision note and explicitly confirm you read this exact proposal, including terms/payment wording/commercial source, and are authorized to decide for your company. The note is visible to your company and administrators. Consent starts unchecked; no decision/note is prefilled. Administrators cannot accept/decline on behalf of a client. Completed projects/released handovers and mismatched/disabled customers block decisions.

The terminal decision shows the actual client actor/time/note/consent and the displayed publication version. Export its sanitized decision CSV for the complete fixed public proposal and canonical decision evidence. Exact failed retries retain fields/identity; a changed note/action receives a new identity. Terminal decisions cannot be switched or overwritten. Earlier accepted/declined records remain immutable when private wording or later publications change. An accepted copy cannot be withdrawn with the open-copy withdrawal action. Current-company access governs archived evidence; refresh after read/download errors to retry.

A recorded portal accept/decline is not an external electronic-signature certificate and does not itself update operative contract value, original sale/payment/budget, invoices, execution, credit/refund/replacement settlement or AMC/SLA settings. Those remain separately developed rule-dependent workflows. Client live workflow/export/device acceptance remains pending.

Accounts/assigned manager → Project Financials now shows **accepted additional quoted reference values** separately: subtotal, quoted tax, gross, quoted WHT and quoted receivable, with accepted-offer count. The latest Accepted wording publication counts once per original additional BOQ offer; later private drafts or declined proposals do not erase the earlier accepted reference or add it twice. CSV/PDF retain the same reference-only labels/count/basis and limitations. No wording, actor or private review/cost/source identity is exposed through the financial aggregation.

These are reference values, not operative revenue, tax accounting, a new amount due or extra invoice totals. Original contract/profit/yet-to-invoice/cash calculations stay unchanged, and missing original budget/profit values remain unknown. Actual business rules for operative contribution/recognition/credits/replacements/settlement must be established before that integration. Client live acceptance remains separate and pending.
