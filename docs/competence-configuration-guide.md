# Competence configuration

An active administrator opens **Overtime & performance → Competence configuration**, then chooses **Load competence configuration**. This is the first DEV-027 increment: versioned manual criteria and actual assessor designations. Actual employee assessment and practical/quiz result recording use the separate [Competence assessments](competence-assessments-guide.md) register. Configuration itself does not review an assessment, issue certificates, award employee skills or suggest/assign resources. Training attendance/learning credit remains separate.

Choose **New competency definition** and enter the actual competency title and intended skill label. Use **Add practical step** for each actual practical checklist step and explicitly mark the mandatory steps. New steps start with blank labels and an unchecked mandatory choice; development supplies no business checklist. Enable the optional quiz only when it is part of this actual competency. The confirmed administrator defaults are pass mark 70% and certificate validity 12 months. Each definition may configure those values; whole months are required. Set an expiry-warning lead time explicitly if known: its blank default is retained as unconfigured, never silently filled. These are saved criteria/settings, not a running certificate-expiry or assessment service yet.

Choose Active or Inactive explicitly and enter the actual revision reason. Active means available criteria for a subsequent assessment implementation, not an issued skill or staff certification. Future pass evaluation must use every mandatory practical step and, if the quiz is enabled, actual quiz score >= the configured pass mark. Nonmandatory step failure alone does not replace that rule.

**Revise [competency title]** copies that exact current definition into the editor and starts a blank reason. Save a fresh full revision; prior checklist IDs/text/mandatory choices, settings, availability, actual administrator/server time/reason remain immutable. Active/inactive corrections use the same versioned path. Technical limits are 100 practical steps, 1,000 characters per step, title/skill up to 200 characters, pass mark 0–100%, validity 1–1,200 whole months and explicitly configured warning lead time 1–36,500 whole days. These are input bounds, not business standards or targets.

Under **Actual assessor designations**, select an actual account, its actual Site Engineer or Senior technician qualification, Grant / restore or Revoke and a reason. Every selection starts blank. This records the administrator's explicit qualification decision; no person is selected or declared senior automatically. Current active internal staff are eligible for an active designation; a retained designation for a disabled/transferred account can still be reasonedly revoked. Site Engineer/senior technician designation grants no global portal role, project membership, assessment reviewer or certificate-issuer power. Team Lead/PM assessment review (different account from assessor) and HR/Admin issuance remain subsequent workflow requirements.

Context and history are administrator-private. HR-only, PM-only, ordinary staff, clients and disabled administrators cannot enumerate this configuration or candidate directory through this screen/RPC/table. Candidate data contains basic account identity only. Later assessment read access must be granted for its specific current actual workflow, not by opening this entire directory/history to staff.

Unchanged uncertain saves retain their request identity and previous revision through refresh; a server acknowledgement cannot create a duplicate revision. A changed field/reason is a new request. Refresh after an error; if another revision has superseded a request that never saved, explicitly reopen the latest criteria or reselect the actual assessor account before a new action. Reconcile immutable history before changing an uncertain request. Successful saves clear the editor/person choices. Failed reads, changed profile/authority, unmount and late responses do not restore stale private data.

**Export private competence configuration CSV** includes accessible frozen criteria and designation revisions with actual actor/server time/reason. Original revisions cannot be edited/deleted through the application. No production criteria, people, designations or certificates have been supplied by development. Client-owned signed-in populated workflow/export/device acceptance remains pending.

The assessment register now supports version-pinned actual outcomes and current explicitly designated assessor authority. Next DEV-027 scope: separate eligible Team Lead/PM review; HR/Admin issuance; certificate validity/expiry warning/renewal and issued employee skill profile used by Configurator resource suggestions. Current Configurator worker allocation lists eligible assigned people via `project_allocation_people`; it has no certificate-backed skills/suggestion model yet. Resource selection stays manual. Do not claim competence, training or CRM complete.


Certificate issuance/expiry is a separate bounded DEV-027 increment: [Competence certificate records](competence-certificates-guide.md). HR/Admin explicitly issues only from a current independently Approved Pass receipt; dates/settings and original evidence are frozen, with private own/HR access and reasoned immutable revocation. No automatic renewal, certificate-backed skill/profile/resource suggestion or training-credit effect is added in that increment. Both requirement documents contain validation/release and precise resume; earlier future-work paragraphs describe historical increments. Client acceptance remains pending.
