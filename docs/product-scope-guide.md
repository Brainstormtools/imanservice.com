# Product board additions, moves and retained history

Prepared increment; consult the latest requirement-document checkpoint for actual release status. No actual products, owners, BOQ lines or assignments are seeded.

An authorized commercial Deal owner, Sales Manager or Admin can open **Product board changes and retained history**. Choose Add or Move, an actual target board not already represented in this Deal, an optional actual eligible product owner, an actual product estimate and reason. Move also requires the exact original active product. All choices/estimates start blank; unassigned remains unassigned. Review the described change and confirm explicitly.

Target board must be active, currently accessible and support the Deal's existing shared stage. Product owners must be actual active staff eligible for the target board. Source and Deal versions are checked again after transaction locks. New products do not copy BOQ, custom-field values, survey/design/BOQ completion flags, staff memberships or project templates. The original shared Deal/customer/owner/stage is preserved; the user reviews its estimate separately rather than an invented total being recalculated.

A Move adds the new product and retains the source product as Dropped with the actual reason. Original BOQ lines, custom-field receipts, survey/design flags and activities stay on their original record. Existing quote calculations already exclude dropped products; the old BOQ is retained rather than silently moved, duplicated or deleted. Frozen published/private quotation snapshots are unchanged. Draft quotation versions advance so stale publish attempts reject and actual staff must review the new scope and enter new BOQ content.

Documented conservative assumption: explicitly withdraw current Published quotations before changing scope. Accepted quotations, Won/Lost or converted scope use their separate change workflow. Existing target products are never duplicated or silently restored; use their existing controls and current versions. No later project/finance adoption behavior is changed here.

A stable request ID preserves one immutable actual actor/server-time/reason/before/after receipt for an exact uncertain retry. Current commercial authority is required to read the retained change history and its private CSV. Clients and unrelated/product-only staff cannot change commercial scope or read its internal evidence. Revoked current Deal/board authority rejects a change without partial writes.

The Deal stage bar sends eligible ordinary stage changes through the existing checked save workflow and exact Deal version. Won links to accepted-quotation conversion; Lost links to the actual reason/explanation form. No required contact, value, meeting, follow-up or quotation prerequisite is skipped.
