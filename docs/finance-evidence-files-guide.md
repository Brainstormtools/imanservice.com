# Private finance evidence files

Expense receipts and loan/advance agreement files are optional evidence alongside the existing text reference. Uploading proof never approves a document or transfers money. Signed-in/browser/export/device acceptance remains client-owned.

## Loan and staff-advance agreements

Existing Accounts/Admin users open **Finance & expenses → Loans & advances**, select an actual record and explicitly choose **Load loan agreement files**. The file panel is not available to ordinary staff, project managers, clients or an advance recipient solely because they are the recipient.

On Draft/Rejected records, choose an actual PDF/image, enter the actual upload reason and upload. Existing technical limits are 10 MB per file, 10 active and 20 registered files including retained history. The portal validates filename/extension/MIME and file prefix, uses a private bucket and never overwrites an existing object. A lost response can be reconciled by loading files and retrying the exact upload; changing file/reason while an upload is unresolved requires reconciliation or explicit discard. Discard applies only to an owned unregistered upload.

Download uses current authenticated Accounts/Admin access. Exclude/restore needs an editable source/version and reason; original registered files and action history stay private and retained. Revoked access removes even an uploader's registered/orphan download rights. Missing/changed metadata is flagged and prevents download/restoration or review as applicable. A file upload is evidence, not proof that somebody legally signed or approved the agreement.

Submitting and independently approving a loan/advance freezes the exact current file basis with complete source/actor/server-time evidence. Text-reference-only records remain valid; no historical proof approval is fabricated. Submitted/Approved/Cancelled records are read-only for file changes; use the existing rejection/return workflow before draft corrections. File changes advance the loan version, so refresh stale financial forms before acting. Loan principal, repayment terms, approval roles, cash posting/reversal and payroll rules are unchanged.

**Export private loan agreement file register CSV** includes the visible file register and immutable attachment/exclusion/restoration/submission/approval snapshots. Treat it as private financial information. No cash transfer is initiated by agreement-file actions.

## Supplemental cash-movement files

Accounts/Admin opens **Finance & expenses → Cash records**, chooses an actual entry and selects **Load cash evidence files**. Optional private files added here are clearly supplemental evidence added after posting. They do not change the original financial entry, source version or approval. Choose an actual PDF/PNG/JPEG/WebP up to 10 MB and enter the actual reason. Each entry retains at most 20 files. Refresh after another user changes evidence. Uncertain responses can be reconciled by refreshing and retrying the exact file/reason; discard only an unresolved owned unregistered upload.

Registered files are immutable. Correct evidence by adding another actual file and reason; earlier evidence stays retained. Current Accounts/Admin access is required for authenticated download and **Export private cash evidence file register CSV**. The private CSV includes the current cash record and immutable supplemental/reversal history. Missing or changed metadata blocks file download and is flagged; retain the original registration. Revoked access removes access even for the uploader.

Reversed cash entries retain their files and history but accept no new attachments. Existing reversal authority, source-version and repayment-order rules apply. Reversal archives original/updated cash records and the observed supplemental file state, including unavailable metadata. Supplemental file availability is not a new financial reversal policy. Historical cash entries have no invented file approval. No posting, transfer, repayment, salary effect or retrospective approval is caused by these file controls.

## Supplemental vendor-payment files

Existing Accounts/Admin opens **Vendor bills & payables → Payments → actual entry → Load payment evidence files**. These private files are supplemental proof added after posting, not retrospective bill/payment approval. Choose an actual PDF/PNG/JPEG/WebP (up to 10 MB), enter the actual reason and upload. At most 20 registered files are retained per payment. Refresh/retry the exact pending upload to reconcile a lost response; discard applies only to an owned unregistered upload. Corrections append another actual file and reason; earlier proof stays retained.

Authenticated download and **Export private payment evidence file register CSV** include original payment details, actual uploader/server time and immutable supplemental/reversal snapshots. Missing/changed metadata blocks download and is flagged. Current Accounts/Admin access is required even for the original uploader. Purchase-only access to bills does not grant access to payment proof.

Reversed vendor payments accept no new attachments. Existing separate Admin reversal and current bill-version checks remain unchanged. Reversal archives the before/after payment and observed proof, including unavailable metadata; optional proof availability does not add a financial reversal rule. Attachment does not change bill version, payment amount, balance, approval or evidence reference and transfers no money. Bill invoice files follow the separate match/approval workflow below. Taxes and credit-note policies remain separate.

## Vendor bill invoice files

Existing Accounts/Admin opens **Vendor bills & payables → Bills → actual bill → Load bill invoice files**. On Draft/Held bills, choose an actual PDF/PNG/JPEG/WebP and enter an actual upload reason. Files are optional: the existing text invoice reference remains valid. Technical limits are 10 MB per file, 10 active and 20 registered files including history. File edits advance the bill version, so refresh stale financial forms. Exclude/restore with a manual reason; registered files remain retained. Authenticated downloads and **Export private bill invoice file register CSV** contain private file selections, original metadata and immutable review/correction history. Purchase-only users may retain existing bill-header access but cannot query these private files.

Matching freezes the actual Matched/Held result, bill, GRN allocations and observed file selection. Matched files are read-only. A separate Admin approves the exact current frozen match and intact selected evidence. To correct Matched proof, use existing reasoned **Return match for correction**, then correct Draft proof and match again. Held bills remain editable. Missing/changed active metadata must be resolved before matching, approval or restoration; reasoned Rework/Cancel remains available under existing financial rules.

Approved/Cancelled files stay read-only, and earlier match/approval receipts remain immutable after rework, cancellation or later payment/reversal. Legacy text-only Matched bills can be approved without inventing a historical file match. Uploading invoice proof does not approve or pay a bill, change a financial amount, transfer money or create a tax/refund policy. Reconcile an uncertain upload using Refresh and the exact file/reason; discard only an owned unregistered upload. Revoked/inactive Accounts loses private access even to their own uploaded files.

## Customer invoice payment receipts

Open **Invoices and payments → actual invoice → Payment history → actual claim → Load payment receipt files**. The original claim submitter or Admin may attach optional actual PDF/images while the claim is Pending and the invoice is Issued. Enter an actual reason; exclude/restore only on the exact current editable receipt version. Technical limits are 10 MB, 10 active and 20 retained files. Registered originals and immutable history remain private and retained. Uploading never verifies payment.

Existing invoice read scope governs receipt downloads/CSV: same-company authorized readers gain no edit or review rights. Other companies, inactive/moved accounts and ordinary team/Accounts roles gain no invoice-file access. **Export private payment receipt file register CSV** includes the exact current claim and immutable receipt/review evidence. Treat it as private payment information. Scope changes/failed loads clear old private views.

Admin explicitly loads the actual current receipt register and uses **Save payment review against loaded receipts**. Manual verification against the bank statement freezes the exact current claim and selected receipt evidence; stale versions or changed claim snapshots are rejected. Missing active metadata must be resolved before verifying; current reject/reverse rules retain unavailable proof without blocking legitimate correction. Reject/reverse requires the existing actual reason; verification has no invented mandatory note or distinct reviewer rule. Verified/Rejected/Reversed files are read-only. Reference-only claims remain valid, and old verified claims have no invented prior file approval. Refresh the portal after release before review; old unversioned review is no longer accepted.
