# Phase 2 — interim Admin manual operating guide

**Interim only: the original Phase 2 SRS is active and incomplete.** The user clarified that the original requirements must be fulfilled. This guide provides temporary manual operating options; it neither closes Phase 2 nor removes any software requirement. Earlier manual-only completion claims are superseded. Actual project work, permissions and client acceptance remain separate.

## Manual operating steps

| Work | Admin method in the existing portal | Original software still required |
|---|---|---|
| Route/device work tasks | In the actual project's **Tasks and team**, use **Add task**, enter the actual task, select an actual authorized assignee if appropriate, set priority/deadline and add the actual checklist. Record route/device identity in the task title or checklist. Before work starts, use the Configurator's task-route reference panel to explicitly link the actual route revision. | Automatic task generation per route/device and route-level aggregate execution reporting. |
| Task hierarchy and predecessors | Keep the actual grouping, parent/child task IDs and predecessor order in a manually maintained project plan. The existing project change record's proposed scope/schedule-impact/evidence fields can record the actual plan and revision reference. Follow its existing review rules when a change requires approval. Admin checks readiness/predecessors before manually scheduling the successor. Task names/checklists can carry the actual grouping reference. | Structured editable hierarchy/dependency graph and automatic predecessor enforcement. Text references are not machine-enforced relationships. |
| Schedule and changes | In **Project worker allocation → Assigned work schedule**, choose actual authorized worker, project/task, description, location and actual planned start/end. Manually review availability, working calendars and predecessors before saving. Use reasoned schedule revisions/cancellation, not automatic rescheduling. Existing overlap, employment, leave, project-scope and completed-work guards continue to apply. | Automatic dependency-driven rescheduling and versioned whole-project schedule baseline comparison. |
| Standards and imports | Enter actual approved task-library standards and template parameters through the existing editors; preview the plan and check quantities/time before conversion. Existing supported import formats can be used as provided. Enter unsupported parameterized data manually; do not treat it as an implemented importer. | Broader parameterized standards, device-attribute and route/import integration. |
| People and tools | Manually review current worker allocations, actual skills, authorized accounts and schedules; confirm assignments explicitly. Record actual tool requests, then book eligible delivered tools against actual tasks/intervals through existing tool-booking controls. Keep any individual physical-tool identification/pre-delivery coordination in the Admin's actual manual resource register. | Automatic capacity/skill ranking, individual physical-tool identity integration and pre-delivery/cross-project allocation optimization. Manual coordination does not reserve unreceived stock or bypass booking conflicts. |
| Criteria and handover | Use **Review current handover criteria**, inspect the exact client-visible criteria/readings and selected evidence, then confirm the actual summary and three eligible signers. New handovers freeze that scope automatically and reject stale signing/archive. Existing sign-off and archived-PDF closure remain required. Older signed scopes stay unchanged. | Criteria/evidence integration is implemented in the current tested increment. Route/device metadata reconciliation remains tracked separately; do not substitute manual work for required software. |

Manual operation preserves current permissions, required reviews, immutable evidence and protection of started/completed work. It grants no new authority, makes no assignments and changes no production business record by itself. Admin must not rewrite recorded work/cost or use the manual procedure to bypass approval, eligibility, booking or handover guards. A manually checked dependency or resource register is not a new server guarantee.
