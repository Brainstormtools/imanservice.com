# Private lead and Deal files

Prepared increment; consult the latest requirement-document checkpoint for actual applied migration and production status. No actual customer files or business fixtures are seeded.

Open an actual Raw Lead or Deal, then **Load lead files**. Files stay tied to the same underlying enquiry when it becomes a Deal or its product boards change. Current active staff lead/Deal read authority applies to the register and authenticated Storage downloads. Clients and unrelated staff have no access; product-only staff may read an assigned visible Deal's files but cannot change the shared commercial register. Revoked/inactive accounts lose access on the server.

An actual authorized sales owner/manager/Admin can upload to an editable enquiry or open Deal with an actual reason. PDF, PNG, JPEG and WebP are supported, up to 10 MB each, ten active and twenty registered files including retained history. These are technical upload bounds, not invented business evidence requirements. No file or reason is preselected. The browser checks actual byte signatures and MIME/extension agreement; the server independently verifies actual uploaded object ownership, size, MIME, exact lead/file path and current authority. Browser retry digests detect a conflicting uncertain upload; they are not represented as independent server content forensics.

Uploads use unique private paths and never overwrite an existing object. Registration records immutable filename/metadata, actual uploader, server time and reason. An uncertain exact retry reuses the same file/request/path; a changed request meaning is rejected. Failed/revoked reads remove private snapshots/exports, and delayed requests/downloads are suppressed after account/lead scope changes. An unregistered owned upload can be explicitly discarded; registered bytes are retained even after exclusion.

**Exclude attachment file** and **Restore attachment file** require an actual reason and current independent file-register version. Exclusion retains the original registered file, bytes and immutable history; restoration also verifies stored metadata. File state cannot be changed on a closed Deal. Excluded historical files remain downloadable only by currently authorized staff. Registered objects and evidence cannot be overwritten, renamed or deleted through the portal, and retention triggers protect against accidental privileged deletion too.

The current file list and loaded immutable history page can be exported privately to CSV. **Load older lead file history** uses an exact version cursor; the export is explicitly the loaded page, not an assertion that unviewed history was exported. Actual historical records remain stored.

Attachments do not change a quotation, approve a Deal, set an owner, advance a stage, stop the first-response timer or award any credit. Quotation PDFs and actual client acceptance remain separate. All 41 client-owned live/browser/export/device acceptance items remain pending.
