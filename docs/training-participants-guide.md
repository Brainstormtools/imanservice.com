# Training account participant drafts

Open Project training documentation in the Configurator. Save the actual training topic/objective as a Draft first, then choose Revise training participants on that training record. The separate facilitator/participant name text fields remain unchanged.

The picker offers only currently assigned active internal staff accounts for that project. No account is preselected and no project assignment or access grant is created. This first increment covers the project-team roster; client/external participants remain recorded text and are not newly account-linked here. Select every actual account that should be in the new complete roster and enter a manual reason. An empty selection explicitly clears the roster. Maximum 100 distinct accounts. Current assignment/active status is checked again on the server when saving, so refresh after stale access or eligibility errors.

Each save creates an immutable full roster revision tied to the exact Draft training version and previous roster revision. It retains selected account IDs, actual saved names/roles/order, full training snapshot, actual selecting account/server timestamp/manual reason and canonical request. Memberships reference real profile IDs. Later name, assignment or training changes never rewrite the saved evidence. Training changes make earlier rosters historical; a current Draft can receive a new explicit full roster selection. Reviewed or Archived training cannot receive new roster edits. Exact failed retries preserve their identity and selections; changed payloads receive a new identity. Refresh after a stale previous roster error.

Assigned authorized managers and administrators can inspect scoped history and Export training participants CSV. Clients and ordinary workers cannot read this private register, including roster members who are not authorized managers. Exports include full frozen source/account/request evidence and spreadsheet escaping. Revoked/disabled manager access is rechecked. The training view clears stale data when account, role, permissions, active status or project scope changes.

Roster membership does not prove attendance, grant permissions, create approved Training activity hours, change costs/pay/KPIs or award certification. Verified attendance is a later DEV-025 increment. Evidence uploads/approved-activity linkage and competence/certification remain separate DEV-026/027 packages. No attendance thresholds, verification policies or actual participants are supplied by the software release.


## Project-linked session definition foundation

For an existing Draft project training record, choose Revise training session definition. Explicitly choose Client or Internal, select the actual facilitator from active assigned staff accounts and enter a manual reason. All choices start blank on each new definition revision. Saving freezes the exact training/version, previous definition, actual facilitator ID/name/role, selecting account/server time/reason and canonical request. Private CSV retains full history. Current account/assignment/source/previous-version checks and immutable retries protect changes. Later training changes make earlier definitions historical; Reviewed/Archived training blocks new definitions. Existing training records are never classified automatically.

This bounded foundation covers project-linked Client and Internal records. Client training keeps its required project link. Standalone Internal sessions remain pending; the software does not impose project membership on all Internal training as a business rule. Selecting a type/facilitator does not yet enable facilitator attendance marking, uploads, PM/lead/HR approval, client signatory confirmation or learning-hour credit. Existing administrator review is review of the old documentation only; it does not substitute for the newly specified attendance approvals. Next implement standalone Internal session scope and the user-confirmed attendee/time/evidence/approval workflow with explicit access checks.


## Standalone Internal drafts in HR

HR/admin and users with the active Team Lead permission can open Overtime & performance → Internal training. Choose New standalone Internal training. Enter the actual topic/objective, choose an actual active facilitator and enter a manual reason. Type is explicitly Internal and no project is requested or created. HR/admin can select active internal staff; team leads can select themselves or their current direct reports using existing HR reporting relationships. No facilitator is preselected. This does not create or change reporting assignments, salary terms or project assignments.

HR/admin can view and correct all these Draft records; team leads can view/correct only their own drafts. Each revision requires the current version and a manual reason, retains original creator, and appends immutable before/after/request/actual actor/time history with the actual facilitator name/role snapshot. Failed unchanged requests keep both record and request IDs. Changed requests get new identities. Delayed retries acknowledge original saves without overwriting later corrections. Private CSV exports include full saved history; ordinary staff, clients, unrelated leads and a selected facilitator without coordinator permission cannot inspect these private draft histories. Revoked/disabled roles lose access immediately.

These are session-definition Drafts only. Facilitator session-specific access/attendance marking, internal and external attendees, check-in/out, uploaded proof, lead/HR approval, admin attendance corrections and internal learning-hour credit are separate remaining increments under the confirmed requirements. Client training stays project-linked. Existing project roster/type/definition histories and approved Training activity calculations are not changed.


### Session attendee register

For project training, first save an explicit Client/Internal session definition, then open its Session attendee register. For standalone Internal training, use HR → Internal training and open the draft's Session attendee register. The current coordinator access rules apply. Choose actual eligible internal staff accounts or add external attendees using their real name, phone and email; an external account is not needed. New full-list replacements start blank. Select everyone who should remain; saving an empty list explicitly clears the list with a mandatory reason. Prior revisions and their exact source/attendee snapshots stay immutable and exportable as private CSV. Source changes require the current version/definition, while older receipts remain historical evidence. An attendee list is registration only. Facilitator attendance entry, check-in/out, uploads, approval, client confirmation and learning credit are still pending.


### Facilitator-entered attendance times

Open HR → Facilitated training. Only current sessions explicitly assigned to your active staff account with a current attendee register appear; project sessions also require your current project assignment. Administrators see current sessions and can record reasoned corrections. The workspace shows current attendee contacts and latest times, without private coordinator histories. Record actual check-in and check-out in your device timezone, or leave both blank as unrecorded. Blank pairs do not assert absence. Both actual times are required together, checkout must follow check-in and cannot be future. Each save replaces the time list for the exact attendee register and requires a fresh reason. Earlier receipts remain immutable. A source, facilitator or attendee change requires the current register; times are never silently copied into a new register. Refresh after changes. Current CSV exports current session/attendee/time context only. Evidence upload, attendance approval, client session confirmation and learning credit remain pending; recording times awards no hours or KPI credit.
