# Issued employee skills and project worker suggestions

Open **Overtime & performance → Issued skills**, then **Load issued employee skills**. An active internal employee sees their own current profile. Existing HR/Admin can inspect active staff with actual issued skills. Ordinary assessors/reviewers gain no staff directory; external/client or disabled accounts cannot use this screen. No people, skills, standards or assignments are supplied by development.

Skills are derived from actual issued, unrevoked, unexpired certificate evidence for active internal staff. A certificate must already have been issued from actual independently Approved Pass evidence using the [certificate workflow](competence-certificates-guide.md). Draft/record/review alone, training attendance, learning credit or a renewal link is not an issued skill. Multiple valid certificates for the same competency definition and exact frozen issued label provide proof for one skill entry, without duplicate credit. Different actual labels/definitions are not silently treated as equivalent.

The profile shows basic employee identity, actual competency ID/skill and valid certificate ID/issue/expiry/status references, with **Export private issued skill profiles CSV**. It does not expose private qualification/review/issuer reasons, salary or contacts. Refresh rechecks server time, employee status, revocation and expiry. Losing the final valid proof removes the current skill; original certificates/history stay immutable. Later source criteria/reviewer changes do not silently revoke an already-issued certificate. Explicit HR/Admin certificate revocation and fixed expiry remain the existing validity controls.

In the **Configurator**, find **Project worker allocation → Certificate-backed worker suggestions**. Choose an actual **Suggestion project**, then **Load actual project skills**. Choose the exact **Actual issued project skill**, then **Find eligible workers by selected skill**. Both choices start blank; the system does not infer a task requirement, select a person or rank workers.

Only current assigned project managers/administrators may inspect matching evidence for their project. Suggestions are restricted to the workers already eligible under existing project_allocation_people rules, including actual project/task assignments and collaborators. A valid skill does not grant project/task access or reveal otherwise-unassigned staff. Multiple certificates never duplicate a person. The output contains only actual worker ID/name, exact competency/skill and certificate validity references. It does not grant private certificate/assessment or HR-directory access.

Use **Export private skill suggestions CSV** for the selected project and exact skill, with server check time and current evidence. Changing skill hides prior matches/export immediately. Failed reads clear private options/matches/exports; refresh requires a fresh manual skill choice. Account/permission/project changes, switching away and back, unmount and late responses cannot restore old private content.

Matches are evidence for manual planning. They do not assert capacity, availability, schedule coverage or suitability beyond the selected actual skill, and do not automatically assign or schedule anyone. Continue using existing manual allocation controls and their current project/task eligibility and overlap checks. No mandatory task skill, ranking, salary/hour/target/KPI policy or automatic commercial decision is added. Skills/suggestions award no training/learning/pay/Finance credit.
