# Survey CSV batch drafts

Open the Project survey measurements register in the Configurator and choose New survey import draft. Select the actual project and paste actual CSV with these eight headers, in any order: title, location, notes, method, evidence, unit, value, measured_on. No additional, duplicate or missing header is accepted. Enter an explicit decimal value (including signed/zero values, up to six decimal places), actual unit and ISO measurement date. Notes/method/evidence may be blank for Draft staging.

Preview survey CSV shows every supplied data row. Changing CSV clears the preview; preview again before saving. Technical limits: 1–100 rows and 1 MB. The server validates all rows before staging anything. An invalid later row leaves no partial saved batch. Identical rows remain separate ordered input rows; no deduplication or unit conversion is inferred.

Save survey batch draft requires an actual manual reason and records private Draft source evidence only. Revise survey import draft keeps the same project, requires a fresh reason/preview and creates immutable before/after/request/actual actor/time history. Negative values and formula-like notes stay unchanged in the editor; private audit CSV exports use production spreadsheet escaping. Refresh after stale version/access errors.

Assigned managers/administrators can inspect their scoped drafts/history. Clients and ordinary workers cannot. Direct edits/deletes bypassing the workflow are denied. No actual survey registry measurement or review is created by staging. Exact-version administrator batch review/return is available; atomic application is available as a separate administrator action; calculation/unit conversion, BOQ/template linkage and instrument/evidence-upload gaps are separate later work. No real data or standards are supplied by this release.


Administrators can choose Reviewed or Returned for a staged batch version and supply an actual manual reason. Reviewed requires method and evidence on every row, matching the existing survey review requirements. Returned allows incomplete actual fields to be corrected. The receipt freezes the full ordered batch, version, request, actual deciding account, timestamp and reason. Managers can inspect their assigned project receipts and export scoped private review CSV. A revised batch needs its own review; previous receipts remain immutable. A review confirms batch readiness only: it creates no registry measurements and does not approve individual measurements. Application is a separate explicit administrator action. Refresh after stale version/access errors; unchanged failed requests retain a stable retry identity.


After the latest review of the unchanged batch version is Reviewed, choose Apply reviewed survey batch and enter an actual application reason. The confirmation shows the exact version, review and new Draft measurement count. All rows are saved together using the existing measurement validation/history rules; an invalid row saves nothing. Every repeated input row creates a separate generated measurement ID. The application permanently records the full batch/review/request/actual applying account/time/reason and ordered source-row-to-measurement mapping. Export survey batch application CSV retains that private evidence. Each resulting Draft measurement needs its own existing administrator review before archival.

A version can be applied only once. An unchanged failed request retains its retry identity; refresh after a stale-version/review/access error. A revised batch needs fresh review; explicitly applying that new version creates additional measurements, without replacing or deduplicating earlier ones. Check the source rows before applying another version. Later measurement revisions never rewrite the original application snapshot. CSV/XLSX file selection and manual mapping are available as described below.


### CSV/XLSX file selection and manual mapping

Inside a new or revised batch editor, choose Survey CSV or XLSX file. Limits are 1 MB for the source file and decoded data, 1–100 measurement rows and up to 20 source columns. CSV must be UTF-8. XLSX uses values from the first worksheet only; formulas in that worksheet, macros, encrypted/oversized archives and malformed input are rejected by the existing values-only reader. Other worksheets are not imported. Supply ISO date text (YYYY-MM-DD), explicit decimal values and units; Excel date serials, formulas, displayed-number formatting and unit conversions are not inferred.

Every mapping starts blank, even when a header matches a survey field. Choose a distinct source column for each survey field, or explicitly Leave blank for optional notes/method/evidence. Inspect ordered source rows, then Use mapped survey rows. Unmapped columns are excluded. The mapped CSV preserves supplied text, negative signs/precision and repeated input rows. Changing the file or mapping clears earlier mapped CSV/preview. File errors also clear earlier data. Clear survey file removes local source/mapping state; manual pasted CSV remains available.

Use mapped survey rows fills the canonical eight-field editor only. Preview survey CSV is still required before staging; source file selection never saves, reviews or applies measurements. Then select the actual project and enter the real batch reason. Server-side validation/review/application stay unchanged. The original file, filename and column mapping remain local editor context, not an uploaded or immutable file archive; saved canonical rows and subsequent batch/review/application history are the retained evidence. Reloading/closing the editor clears local file state. Separate DEV-023 calculations/template linkage and DEV-024 instruments/calibration/evidence uploads remain pending.
