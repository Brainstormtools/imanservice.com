## Source issues that block direct financial/time imports

- `Project_Management.xlsx`, Project Record N5/O5 sum Invoices F/G, but F is Milestone and G is Invoice Amount; received values belong to H. The same row's X5:AD5 use Expenses H/J, while H is Bill/Voucher, I is Amount, J is Paid Amount and K is Balance Payable. These column mismatches can understate invoices/costs and misclassify payments. Existing later rows also mix formulas and stored values; no balances have been trusted as production accounting entries.
- Project Record receivable formulas use sale value minus received rather than issued invoices minus verified receipts/credits. Yet-to-invoice and trade receivable must remain distinct in the portal.
- The Guide flags two project dates with year 2206 and maps old Cancelled to Closed. These need source review before import; cancellation is not a signed operational or financial closure.
- The receivables/payables tracker includes borrowing-like labels among receivables. Each proposed opening balance needs classification as customer trade, loan principal or advance before import. The portal keeps loan principal separate.
- The tracker labels its last bucket `90+ Days`, but formulas enter it only above 90. The portal uses `61–90 days` and `91+ days` to make boundaries unambiguous. Its 7/30-day windows include today and overlap.
- Staff sheets include typed duration text and time-of-day intervals that can disagree or cross midnight. Imports need explicit start/end/date mapping and reviewer correction; typed text does not override computed actual hours.
