# Private expense product allocation drafts

Accounts or administrator → Finance → Expenses → Private expense product allocation drafts.

Choose an exact Approved PKR project expense. Its recorded category and amount are fixed context. Select existing workstreams from that expense's project and enter actual positive split amounts manually in PKR, up to two decimal places. New source/product/amount/reason inputs are blank. One row per workstream is allowed; the sum cannot exceed the recorded expense. A partial proposal leaves an explicit calculated unallocated remainder. No percentage, distribution weight, salary, rate or assignment is supplied automatically.

Save with an actual revision reason. One versioned proposal is allowed per expense. The server freezes the Approved source and product identities/names, calculates allocated/unallocated totals and retains actual actor/time/reason plus immutable before/after history. A revision fixes the source and requires the displayed current proposal/source versions and a new reason. A source version changed by a separate cash action must be refreshed before saving; allocation does not change that cash record. An original amount/category change requires separate reconciliation. Exact failed/delayed retries return the original proposal without undoing later splits; changed/stale payloads cannot overwrite it. Product labels can change later without rewriting frozen history.

Inspect the saved source and split snapshots; export the private current-draft or revision-history CSV for actual provenance. Existing Accounts permission governs access; clients, assigned managers without Accounts permission, workers and disabled/revoked users cannot read/save these allocation tables. Accounts obtains only sanitized product-choice identities, not extra workstream-plan access. Refresh rechecks access and closes unsaved editors; after a read/download failure, refresh and retry.

These are unapplied classification drafts. They change no approved expense/category/payment, recorded project cost, budget, contract/revenue, labour rate, stock, task or assignment. Labour/net stock allocations and broader product financial reports remain later increments, along with labour/stock costs, office-cost distribution and other category/allocation rules. No new project-closure policy is imposed on an unapplied draft. Actual business splits and reviewer decisions must be entered manually. Client live workflow/export/device acceptance remains separate and pending.

Review or return the exact current draft version with an actual manual reason. Reviewed requires freshly frozen current Approved source amount/category/project/version and product identities. After a separate cash payment changes the source version, refresh and revise the draft using the same actual splits and a new reason before review; cash does not change the allocated cost. Returned can document corrections even when source approval/economic/product evidence became stale. Both actions retain the full allocation and actual source-at-action snapshots, actual actor/time/reason and immutable scoped review CSV. New revisions require fresh review; earlier records stay visible. Failed unchanged actions retry with the same identity. Reviewed remains an internal recorded decision; apply it separately to classify costs.

Apply the exact current Reviewed allocation version with an actual manual reason. The server rechecks freshly frozen Approved source and product identities, saves an immutable applied snapshot and requires the displayed latest application predecessor. Later draft edits/review returns do not change that classification; explicitly replace it with a newly Reviewed version or withdraw it with a manual reason. Withdrawal retains old applied evidence even after a draft revision. Cash-only version changes do not change existing applied splits; a new application needs refreshed draft/review evidence. Economic source changes require reconciliation and are reported fully unallocated rather than inheriting stale splits.

Choose a project in Approved expense costs by product to inspect category/product/workstream amounts, allocated versus unallocated totals and individual expense/application states. Export the report or the immutable application history CSV for provenance. The report partitions each current Approved PKR project expense once and preserves recorded project cost/cash. It excludes labour, net stock, office expenses and product revenue/profit. Those broader allocations remain later increments; no percentage distribution or actual assignment is supplied automatically. Client live acceptance remains pending.
