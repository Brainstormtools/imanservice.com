# Finance evidence file coverage audit

Audited on 20 October 2026 against the user-uploaded IMAN_CRM_Developer_Spec.pdf, Module 4 (pages 25–28), current requirement documents, and the website repository. The PDF is source material for requirements, not authorization to change review roles, accounting policy, external delivery or the separate CRM repository. This is a finance file coverage audit, not a fresh full workbook/41-item acceptance audit.

The original specification explicitly requires customer payment receipt upload on page 25. Inspecting Invoices and payments found reference/notes submission and Admin verification without private file upload. That is a confirmed DEV-048 gap; the new customer-payment receipt increment addresses it against existing payment claims. Existing bank-reference claim access/verification remains authoritative. No new payment method, reviewer, refund, tax or assignment policy is defined by this audit.

All registers preserve actual uploaded metadata, actual account/server time, manual reasons, scoped authenticated downloads and private CSV. Registered objects cannot be overwritten or removed through ordinary portal access, including excluded history. File prefix/MIME checks and client-side retry hashing do not certify a receipt as genuine or provide server-certified cryptographic integrity. Missing/changed metadata is flagged; selected proof must be intact for new approval/verification as applicable. Corrective financial rejection/reversal retains unavailable-proof flags under existing rules. No historical approval is fabricated.

The customer receipt addition preserves current can_invoice access: Admin and current authorized client-company accounts read; only the submitter or Admin edits Pending proof. Same-company read access does not grant edit or verification authority. Existing Accounts/team permission alone does not grant access to the separate customer billing workflow. Verification remains Admin manual bank review. Receipt attachment does not verify a claim, change amount/reference, transfer money or extend another company's access. Rejected/Reversed/Verified proof is read-only. Reference-only claims remain valid with an explicit empty proof basis.

Legacy three-argument review cannot bypass the new exact loaded claim/receipt version requirement. Refresh the portal after release and explicitly load receipts before Admin review. Existing status, credit/balance, duplicate-reference and manual reject/reverse reason checks remain delegated unchanged.

Release gate: complete targeted/full checks, exact preview, only new migration 135 once, live guard/security checks, PR merge, production and served-asset verification before recording this gap as released or considering DEV-048 development completion. All actual signed-in role/upload/download/export/device acceptance remains client-owned and pending. Broader Finance payment-method/status/role parity, tax/refund/bank reconciliation/opening balance/settlement requirements remain separate; this file audit does not claim them complete.
