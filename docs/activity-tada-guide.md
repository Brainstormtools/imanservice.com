# Activity-linked TADA claim drafts

Open **Daily activity log** and the actual eligible activity you recorded, then choose **Load activity TADA claims**. Current activity and existing applicable expense access are both required. Managers and administrators cannot create a claim on another person's activity. Own Internal activities are also supported for Accounts/administrators who already have no-project expense permission. Their source panel explicitly shows **Office / no project**; ordinary staff do not gain Internal expense access. Own Deal activities use the confirmed interim Office / no project scope, Pre-sales / Survey category and required actual Deal number reference described below.

The source panel shows the actual version, location and recorded interval. Enter the actual expense description, payee, voucher/receipt number, expense date, due date, PKR amount, receipt evidence reference/document location and claim creation reason. All fields start blank. No mileage, daily allowance, rate, budget, due date or reimbursement policy is calculated. The server fixes category to TADA for Project/Ticket/Internal or Pre-sales / Survey for Deal, deriving project/task scope from the selected activity and retaining null project/task for eligible Internal/Deal sources; a ticket identity remains in the frozen source evidence without inventing an expense task.

**Create linked TADA draft** creates one ordinary expense Draft and its immutable source record atomically. An unchanged uncertain request returns the same expense rather than creating another. Changed inputs use a new request; the existing actual payee/voucher duplicate guard remains in force. Separate actual expenses may reference the same activity with their own real documents. Do not re-enter an expense already recorded elsewhere.

Open **Work expenses** to revise the actual draft or submit it through the existing separate approval workflow. Activity approval is not expense approval or payment. This increment does not change the current administrator expense approval or Accounts payment-record authority, route a message, initiate a transfer or alter salary/learning calculations. Receipt references remain references; the separate optional [Expense receipt register](expense-receipts-guide.md) supports actual expense files, and activity attachments are not copied or granted to Finance automatically.

The original activity/version/time/location and initial expense snapshot, request, actual actor/server time/reason remain immutable. Later expense revisions are shown separately. The general expense editor can revise ordinary draft fields but cannot change a linked claim's original category, project/task scope, author or frozen Deal reference. Cancelling or revising an activity makes its original source historical; it does not silently cancel, approve, suspend or pay an existing expense. Fresh creation requires the exact current non-void activity version. Existing finance review/payment/cancellation rules continue to apply independently.

Activity source history and **Export activity TADA source CSV** are private to current activity and expense permissions. In an actual TADA or Pre-sales / Survey expense, choose **Load expense activity source** to inspect the permitted frozen source. Accounts' expense access alone does not expose an otherwise private Draft activity; an empty visible source list is not proof that no historical link exists. The original expense and its ordinary finance audit remain available within Finance's existing scope.

Refresh after a failed request. Failed reads/writes remove stale private source views and exports; manual failed draft inputs remain local for a safe refresh in the same scope. Account/role/permission/activity changes clear the form, and delayed responses cannot restore a prior private context. Use actual manually maintained business records; no production test fixture is supplied. Client-owned signed-in workflow, populated export/private evidence and device acceptance remain pending.

## Confirmed interim Deal claims

For your own current Deal activity, existing Accounts/admin no-project expense authority is required in addition to current Deal/work access. Load activity TADA claims and inspect the explicit Office / no project scope and Pre-sales / Survey category. Enter the actual Deal number in the required reference field, starting blank, plus actual payee/voucher/dates/amount/receipt reference/reason. The Deal register has no separate business number field: no title or UUID is used as an invented number, and development does not verify the manually supplied number against an absent register. The server retains the actual Deal ID alongside this reference in immutable source/initial expense evidence. The resulting ordinary Draft uses separate existing expense approval and private receipts.

Finance displays the expense reference and retains it in private ledger CSV/PDF and source evidence. Existing business edits cannot recategorize or move the claim or rewrite that reference. Winning/conversion does not transfer Office expense to project costs. First-class Deal attribution with automatic movement to the won project is explicitly logged as a future DEV-052 extension. Ordinary Sales access alone does not grant Office expense access. All signed-in acceptance remains pending.
